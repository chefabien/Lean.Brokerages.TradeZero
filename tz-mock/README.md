# tz-mock

tz-mock is an in-memory mock of the [TradeZero Trading API](https://developer.tradezero.com/docs/TradeZeroAPI/tradezero-developer-api), for testing a connector against deterministic market scenarios.

- It serves the same REST paths and JSON shapes as `https://webapi.tradezero.com/v1/api`. Shapes were checked against the paper API.
- It accepts any `TZ-API-KEY-ID` / `TZ-API-SECRET-KEY`.
- Each distinct `TZ-API-KEY-ID` is an **isolated session** with its own scenario, virtual clock and portfolio. Parallel test runs only need different fake keys.
- Prices come from OHLCV CSV files. Time moves only when you call `POST /mock/time`.
- Behaviour, sources and known differences are tracked in [docs/api-notes.md](docs/api-notes.md). That file is the reference: when the real API turns out to behave differently, fix the mock and update it.

REST only: there are no WebSocket streams, options or rate limits.

## Setup

```bash
conda env create -f environment.yml      # creates env "tz-mock" (python 3.14) with the dependencies
conda activate tz-mock
python -m tz_mock                        # serves on http://127.0.0.1:8000 (TZ_MOCK_HOST / TZ_MOCK_PORT)
pytest -q
```

tz-mock is never installed: run both commands from the repo root, where the `tz_mock/` package lives.

Point the connector's base URL at `http://127.0.0.1:8000` in place of `https://webapi.tradezero.com`.

## Control endpoints (`/mock`)

All control endpoints except `GET /mock/scenarios` need the `TZ-API-KEY-ID` header, because it selects the session.

| Endpoint | Body | Effect |
|---|---|---|
| `GET /mock/scenarios` | | Lists `[{name, description}]` |
| `POST /mock/scenario` | `{"name": "basic_fills", "params": {"cash": 50000}}` | Restarts the session on that scenario. The portfolio, orders and locates are zeroed, and the clock goes to the scenario start. `params` override scenario attributes. |
| `POST /mock/time` | `{"to": "2026-01-05T15:00:00Z"}` | Moves the clock forward. The time must be later than now. Bars in `(now, to]` are replayed against working orders. Returns `{now, fills}`. |
| `GET /mock/state` | | Debug view: scenario, now, last prices, working orders |
| `DELETE /mock/session` | | Forgets the session |

A session that never chose a scenario starts on `basic_fills`.

```bash
H='TZ-API-KEY-ID: my-test'
curl -s -H "$H" -X POST localhost:8000/mock/scenario -H 'Content-Type: application/json' -d '{"name":"partial_fills"}'
ACC=$(curl -s -H "$H" localhost:8000/v1/api/accounts | python -c 'import json,sys;print(json.load(sys.stdin)["accounts"][0]["account"])')
curl -s -H "$H" -X POST localhost:8000/v1/api/accounts/$ACC/order -H 'Content-Type: application/json' \
  -d '{"securityType":"Stock","symbol":"THIN","side":"Buy","openClose":"Open","orderType":"Market","orderQuantity":200,"timeInForce":"Day"}'
curl -s -H "$H" -X POST localhost:8000/mock/time -H 'Content-Type: application/json' -d '{"to":"2026-01-05T14:40:00Z"}'
curl -s -H "$H" localhost:8000/v1/api/accounts/$ACC/positions
```

## Scenarios

| Name | What it tests |
|---|---|
| `basic_fills` | AAPL and MSFT over two sessions (2026-01-05/06). Market, limit and stop fills, Day expiry at 16:00 ET, overnight positions. |
| `partial_fills` | THIN, a low-volume symbol. Only 10% of each bar's volume can fill, so orders go `PartiallyFilled` across bars. |
| `short_htb` | Shorting and locates with live behaviour. AAPL is easy to borrow. HTBX is hard to borrow and has locates at $0.03. NOLOC has no locate supply. SUBP is under $0.50 (R40). |

### Adding a scenario

Create `tz_mock/scenarios/my_scenario.py`:

```python
from datetime import UTC, datetime
from . import Scenario, register

@register
class MyScenario(Scenario):
    name = "my_scenario"
    description = "What this scenario exercises"
    bars = ["AAPL_1min.csv"]                       # files under data/bars (or absolute paths)
    start = datetime(2026, 1, 5, 14, 31, tzinfo=UTC)
    participation = 0.5                            # optional: cap fills at 50% of bar volume
    htb = {"XYZ"}; locate_price = {"XYZ": 0.05}    # optional: hard-to-borrow + locate offers

    def on_order(self, broker, order):             # optional: return a text to reject the order
        return "R06: This symbol is restricted from trading at this price" if order.symbol == "XYZ" else None

    def on_bar(self, broker, bar):                 # optional: custom logic on each replayed bar
        ...
```

Modules in that package are discovered automatically.

Bar CSVs have the columns `ticker,datetime,open,high,low,close,volume`. `datetime` is an ISO timestamp with a timezone and marks the **end** of the bar. The bundled files are generated by `python scripts/make_bars.py`.

## Fill model (summary)

- The current price is the close of the last bar at or before the virtual clock.
- Market orders and marketable limits fill immediately at the current price. Resting limits and stops fill when a later bar's range crosses them, with gap-aware prices.
- Each bar can fill at most `volume × participation` shares per symbol.
- POST `/order` returns `PendingNew`, like the paper API. Read the order back to see `New`, `Filled` or `Rejected`.

## Checking against the real API

`scripts/compare_paper.py` calls the same read-only GET endpoints on the paper API and on a running mock, then diffs the JSON key structure. It uses your paper keys:

```bash
export TZ_API_KEY_ID=... TZ_API_SECRET_KEY=...
python scripts/compare_paper.py --mock http://127.0.0.1:8000
```
